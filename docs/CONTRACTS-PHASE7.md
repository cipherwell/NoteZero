# NoteZero — Phase-7 (increment 8) contracts: create menu, code formats, PDF documents

Frozen interfaces/behaviour for the create-menu increment. The E2E and Robolectric tests address
these names only; renaming requires updating the tests and this file in the same commit.

## 1. Item model

| Contract | Value |
|---|---|
| `ItemKind` | `NOTE`, `CODE_FILE`, `PDF_FILE` — enumeration order is frozen (payload ordinals 0/1/2). New kinds are appended only. |
| PDF item content | exactly one attachment with `mimeType = "application/pdf"`, display name `document-<yyyyMMdd-HHmmss>.pdf` (UTC-independent local time), bytes = one blank A4 PDF page generated by `model/BlankPdf.create()`; `body` empty, `title` = the display name |
| PDF failure atomicity | if the attachment import fails, the just-created item is trashed again before `createPdf` returns null; no empty PDF row and no orphan blob |
| Code formats | `code/CodeFormats.all` (27 entries) — extension + nearest lexer; `resolveName` keeps a typed known extension, `applyFormat` rewrites otherwise |

## 2. Create menu UI

| Element | Contract |
|---|---|
| FAB | tag `new_note_button`, icon-only, content description `Create` (string `cd_notes_create`), hidden in Trash |
| Sheet | in-window overlay: root `create_overlay`, dismiss scrim `create_scrim`, card `create_sheet`; options tagged `create_note`, `create_drawing`, `create_code`, `create_pdf`; dismiss by back/tap scrim |
| Drawing option | creates a `NOTE` and opens the editor with the drawing canvas visible once (request consumed on first composition; never re-opened after rotation/back) |
| Code option | opens the format dialog: field tag `code_dialog_field` (pre-filled `untitled.<default ext>`), chips `code_format_<ext>`, confirm `code_dialog_confirm`, cancel `code_dialog_cancel`, inline error `code_dialog_error`; created item is `CODE_FILE` titled with the resolved name and **opened in the code editor** (`code_editor`), as are `CODE_FILE` rows tapped in Notes |
| PDF option | creates a `PDF_FILE` and opens the PDF viewer; failure shows the non-secret `create_failed` message |
| Creation errors | `NotesViewModel.createError` (boolean) drives a single dismissible dialog; it never carries item content |

## 3. PDF viewer

| Element | Contract |
|---|---|
| Screen | root tag `pdf_viewer`; title tag `pdf_title` (item title or attachment display name); back tag `pdf_back` (system back closes too) |
| Pages | each rendered page tag `pdf_page`; page indicator `Page x / y`; `pdf_pages_capped` when > 8 pages |
| Errors | `pdf_error` for unreadable/corrupt document; `pdf_loading` while decrypting/rendering; never echoes content or crypto errors |
| Export | `pdf_export` opens the explicit `pdf_export_warning` dialog; confirm `pdf_export_confirm` → SAF `CreateDocument("application/pdf")`; cancel `pdf_export_cancel`; marked `bindable=false` external-activity bracket from the repository deferral API |
| Rendering bounds | ≤ 8 pages, ≤ 1600 px long edge, ARGB_8888, bitmaps recycled on dispose; decrypted cache file deleted before frames are shown (`AndroidPdfPageRenderer`) |
| Security | viewer reads only `repository.attachmentBytes(itemId, attachmentId)`; no other file/cache persists; FLAG_SECURE is app-wide |
